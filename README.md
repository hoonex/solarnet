# SolarNet

SolarNet is a local-first multiplayer engine for turn-based games.

The first target is a 2D mobile game where nearby devices can play together without a traditional game server. The engine separates physical transport, room/lobby lifecycle, authoritative turns, and deterministic game-state recovery.

## Current milestone — 0.9

- host-authoritative turn ordering and duplicate/out-of-order protection;
- Google Nearby advertiser/discoverer transport for Unity Android;
- explicit Bluetooth-only Android transport using secure Bluetooth Classic RFCOMM;
- logical peer identity handshakes independent from Nearby endpoint IDs or Bluetooth connection/MAC identity;
- explicit human authentication-code confirmation before Nearby acceptance;
- paired-device Bluetooth path that avoids scan permission;
- deterministic `ISolarGameStateMachine`, SHA-256 state digests, action-journal replay, and authoritative snapshot fallback;
- room join admission with protocol + game compatibility checks;
- authoritative roster, Ready state, host Start, and stable reconnect-to-existing-slot semantics;
- separate `roomId` / `gameSessionId` multiplexing over the same live transport;
- active-match reconnect recovery: a client can reconnect to the same host and replay missed commits before continuing play;
- Unity Package Manager Diagnostics sample for two-phone transport testing;
- Grid Duel deterministic 5x5 game with local loopback and real two-phone Nearby/Bluetooth modes;
- native Android RFCOMM probe APK generated by CI;
- recovery CI covers digest corruption, turn gaps, journal replay, journal-eviction snapshot fallback, duplicate committed packets, and forced active-match disconnect/reconnect.

## Unity flow

1. Choose `NearbyTransport` or `BluetoothClassicTransport` on Android.
2. Attach `SolarRoomSession`.
3. Connect peers, join the room, confirm Ready, and wait for `GameStarted`.
4. Create `SolarTurnSession` with `SolarGameStartInfo.GameSessionId` over the same transport.
5. Attach an `ISolarGameStateMachine` for deterministic validation, hashing, journal replay, and snapshot recovery.
6. If a client link reconnects during a match, rejoin the room with the same peer ID and call `RequestResyncAsync()` before accepting new local input. The Grid Duel networked sample does this automatically.

For transport-only device checks, import **SolarNet Diagnostics**. For a playable game, import **Grid Duel** and add `GridDuelNetworkedDemo` to an empty GameObject.
