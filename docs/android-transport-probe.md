# Android Transport Probe APK

The repository builds a small native Android debug APK that tests the Bluetooth Classic bridge without Unity. This narrows physical-device failures to the radio/native layer before involving Unity, rooms, or turn-state code.

## What it tests

- Android 12+ `BLUETOOTH_CONNECT` runtime permission;
- paired-device enumeration;
- secure RFCOMM server creation with the SolarNet service UUID;
- client `createRfcommSocketToServiceRecord` connection;
- framed bidirectional byte transfer;
- multiple accepted client sockets on one host;
- disconnect/error callbacks.

The probe sends UTF-8 `PING <timestamp>` frames. A phone in Host mode automatically replies with `PONG <timestamp>` to the same RFCOMM connection.

## CI artifact

The `android-transports` CI job builds `:probe-app:assembleDebug`, writes a SHA-256 checksum, and uploads both files as the `solarnet-transport-probe-apk` workflow artifact.

This APK uses the normal Android debug signing key generated by the CI environment. It is for local sideload testing only, not distribution.

## Two-phone procedure

1. Pair phone A and phone B in Android Bluetooth settings.
2. Install the same probe APK on both phones.
3. Grant Bluetooth permission on both.
4. Phone A: tap **HOST: start RFCOMM server**.
5. Phone B: tap **CLIENT: refresh paired devices**, then choose phone A.
6. Confirm both logs show `CONNECTED`.
7. Phone B: tap **Broadcast PING**.
8. Confirm phone A logs `PING`, replies `PONG`, and phone B receives the matching timestamp.
9. Repeat several times; optionally connect additional paired clients to the same host.

A successful probe run proves the Java/RFCOMM layer on those physical devices. It does not by itself prove the Unity C# bridge or full SolarNet room/turn protocol; the Unity Diagnostics sample covers that next layer.
