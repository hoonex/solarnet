# Probe evidence field reference

Probe 0.4.0 emits one `SOLARNET_PROBE_RESULT` JSON object per completed or manually stopped timed soak.

## Top-level

- `transport`: `bluetooth-classic` or `nearby-connections`.
- `probeVersion`: Probe APK schema/tooling version.
- `deviceModel`: Android manufacturer/model string from the client phone.
- `sdkInt`: Android API level.
- `androidRelease`: Android release string.
- `evidence.start`: device/build snapshot captured immediately before the timed controller starts.
- `evidence.end`: device/build snapshot captured when the controller finishes.
- `result`: unchanged packet/RTT result generated by `ProbeSoakStats`.

## Evidence snapshot

- `capturedAtEpochMs`: wall-clock capture time for correlating with external logs. RTT does not use this clock.
- `batteryPercent`: integer percentage, or `-1` when unavailable.
- `batteryTemperatureC`: battery temperature in Celsius, or JSON `null` when unavailable.
- `batteryVoltageMv`: reported battery voltage in millivolts, or `-1` when unavailable.
- `thermalStatus`: Android `PowerManager` thermal-status integer, or `-1` when unavailable.
- `sourceSha`: immutable source identity injected by CI, or `unknown` for an unlabelled local build.
- `apkSha256`: SHA-256 of the installed base APK, computed once off the UI thread.

The two evidence snapshots should normally contain the same `sourceSha` and `apkSha256`. A difference is a run-integrity failure and should be investigated rather than normalized away.
